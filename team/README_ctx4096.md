# nGPT против GPT на длинном контексте (4096) — инструкция по запуску на Kaggle

## Что это за эксперимент

Мы уже сравнили GPT и nGPT при контексте 1024 токена. nGPT оказался лучше:
val loss 3.254 против 3.359, по токенам он обучается быстрее в ≈1.41×.
Теперь проверяем то же самое при **контексте 4096**. В статье nGPT выигрывает тем сильнее, чем длиннее контекст.

Меняем только длину контекста. Всё остальное как в прошлый раз:

| | Было | Сейчас |
|---|---|---|
| Контекст | 1024 | **4096** |
| Окон в батче | 64 | **16** (в 4 раза меньше) |
| Окон за один проход | 8 | **2** |
| Токенов на шаг | 65 536 | 65 536 (не меняется) |
| Шагов / токенов всего | 11 826 / 775M | столько же |
| lr | 0.003 у обеих моделей | 0.003 у обеих моделей |

GPT и nGPT обучаются одновременно, каждая модель на своей видеокарте T4.

**Порядок работы:**
1. **Подготовка** (один раз, 5 минут).
2. **Замер скорости** (~25 минут, при открытом браузере): проверяем, что nGPT успеет за одну сессию Kaggle (лимит 12 часов).
3. **Полный запуск** (~10–11 часов, браузер можно закрыть).
4. **Сдать результат.**

Расход квоты GPU: примерно 12 из 30 часов в неделю.

## 1. Подготовка (один раз)

1. Аккаунт Kaggle с **подтверждённым телефоном**: аватар → Settings → Phone Verification = Verified.
   Без этого не будет ни GPU, ни интернета.
2. На kaggle.com: **Create → New Notebook**.
3. Переименуй ноутбук (клик по названию сверху) в **`ngpt-ctx4096`**.
4. Справа, в панели **Session options**:
   - **Accelerator → GPU T4 x2** (именно x2, не P100 и не одна T4);
   - **Internet → On**;
   - раздел **Input** оставь **пустым**.
5. В новом ноутбуке уже есть одна пустая ячейка с кодом. Ниже ты создашь пять ячеек с кодом,
   по порядку. Новая ячейка добавляется кнопкой **+ Code** под последней ячейкой.
   Текст каждой ячейки копируй **целиком**, ничего не меняя (кроме строки `BENCH`, о ней ниже).

### Ячейка 1 — настройки

```python
# ===== Настройки =====
BENCH = True      # True — только замер скорости (шаг 2); False — полный запуск (шаг 3)
CTX = 4096        # длина контекста; 2048 — запасной вариант, если замер скажет, что 4096 не успевает

LR = "3e-3"       # lr обеих моделей (лучший на 775M при контексте 1024)
BUDGET = "775M"
SEED = 42
BATCH = 64 * 1024 // CTX          # окон в батче: токенов на шаг всегда 65 536
MICRO = max(1, 8 * 1024 // CTX)   # окон за один проход по видеокарте: 8 192 токенов, как раньше

SESSION_HOURS = 11.5
TRAIN_TOKENS = "9e8"
REPO = "https://github.com/NordManul/Project_Transformers.git"
PLAN = (f"--n_layer 6 --n_head 6 --d_model 384 --block_size {CTX} --batch_size {BATCH} --micro_batch {MICRO} "
        f"--budgets {BUDGET} --lrs {LR} --seed {SEED} --data_seed {1234 + SEED - 42}")
NAME = f"ctx{CTX}_{BUDGET}_lr{LR}_s{SEED}"

import glob, json, os, shutil, subprocess, time
T0 = time.time()
WORK = "/kaggle/working"
CODE = f"{WORK}/Project_Transformers"
DATA = f"{WORK}/data/owt"
if not os.path.exists(CODE):
    subprocess.run(["git", "clone", "--depth", "1", REPO, CODE], check=True)
os.chdir(CODE)
print("код:", subprocess.run(["git", "rev-parse", "--short", "HEAD"], capture_output=True, text=True).stdout.strip())
import torch
print("torch", torch.__version__, "| GPU:", [torch.cuda.get_device_name(i) for i in range(torch.cuda.device_count())])

OUT = f"{WORK}/runs/{NAME}"
print("РЕЖИМ:", "замер скорости" if BENCH else "полный запуск")
print("PLAN:", PLAN)
print("OUT:", OUT)
```

## 2. Замер скорости (~25 минут, браузер не закрывать)

1. Проверь, что в ячейке 1 стоит `BENCH = True` и `CTX = 4096`.
2. Запусти по очереди **ячейку 1, ячейку 2, ячейку 3**. Запуск — кнопка ▶ слева от ячейки или **Shift+Enter**.
   Ячейки 4 и 5 при `BENCH = True` ничего не делают, их можно не запускать.
3. **Ячейка 1** должна напечатать:
   ```
   код: <короткий хэш>
   torch ... | GPU: ['Tesla T4', 'Tesla T4']      ← обязательно две T4
   РЕЖИМ: замер скорости
   PLAN: --n_layer 6 --n_head 6 --d_model 384 --block_size 4096 --batch_size 16 --micro_batch 2 ...
   ```
   Если GPU одна или их нет, проверь Accelerator (пункт 1.4).
4. **Ячейка 2** идёт ~14 минут. В конце печатает `"train_tokens": 900000000`.
5. **Ячейка 3** идёт ~5–10 минут. В конце будут строки такого вида:
   ```
     gpt: 30,000 токенов/с, память 6.1 ГБ
     ngpt: 21,000 токенов/с, память 8.0 ГБ
   ```
   Числа здесь для примера.
   Строку «Оценка: ~… ч» **не используй**: она занижена, когда модели идут параллельно.

### Как решить, какой контекст запускать

Смотри только на скорость **ngpt** (токенов/с):

| Скорость ngpt | Что делать |
|---|---|
| **22 000 и больше** | Контекст 4096 успевает. Переходи к шагу 3, `CTX` не меняй. |
| **меньше 22 000** | Не успеет за 12 часов. В ячейке 1 поставь `CTX = 2048`, снова запусти ячейки 1 и 3 и посмотри скорость ngpt. Если она 22 000 и больше — запускай шаг 3 с `CTX = 2048`. Если меньше — напиши в чат, не запускай. |

Откуда 22 000: nGPT должен пройти 775M токенов (плюс ~8% на проверки) примерно за 10.9 часа.
Это всё, что остаётся от 12 часов после подготовки данных и с запасом.
775 000 000 × 1.08 / (10.9 × 3600) ≈ 21 300 токенов/с.

**Если в ячейке 3 ошибка `CUDA out of memory`**: в ячейке 1 замени строку `MICRO = ...` на `MICRO = 1`,
запусти ячейки 1 и 3 заново. Если ошибка другая — пришли в чат последние ~30 строк вывода.

**Напиши в чат** две строки замера (`gpt: …` и `ngpt: …`) и какой `CTX` выбран.

Когда замер готов, выключи интерактивную сессию кнопкой **⏻** вверху справа, чтобы не тратить квоту.

## 3. Полный запуск (~10–11 часов)

1. В ячейке 1 поставь **`BENCH = False`**. `CTX` — тот, что выбрали на шаге 2.
2. Проверь справа: **GPU T4 x2**, **Internet On**, **Input пустой**.
3. **Save Version** (кнопка вверху справа) → **Save & Run All (Commit)** → **Save**.
4. Если интерактивная сессия ещё включена, выключи её кнопкой **⏻**.
   Браузер и компьютер можно закрыть: всё идёт на серверах Kaggle.

### Проверка через ~20 минут

**Your Work → `ngpt-ctx4096` → версия, которая сейчас идёт → Logs.** Должно быть:

```
код: <короткий хэш>
torch ... | GPU: ['Tesla T4', 'Tesla T4']
РЕЖИМ: полный запуск
PLAN: ... --block_size 4096 --batch_size 16 --micro_batch 2 ...
Замер пропущен (BENCH = False)
Часов на обучение: 10.9...
План: 2 прогонов, устройства ['0', '1'], лимит 10.9... ч
[0] gpt_775M_lr0.003: старт (lr 0.003, 11826 шагов, 775M токенов)
[1] ngpt_775M_lr0.003: старт (lr 0.003, 11826 шагов, 775M токенов)
```

Дальше лог надолго замолкает — **это нормально**: подробный ход обучения пишется в файлы, а не в лог.
Если вместо «полный запуск» написано «замер скорости», значит забыли поставить `BENCH = False`.
Тогда отмени запуск (**Active Events → ⋯ → Cancel**), исправь и запусти заново.

### Как понять, что всё закончилось хорошо

Примерно через 6–7 часов в логе появится строка GPT, а ещё через 3–4 часа — строка nGPT:

```
[0] gpt_775M_lr0.003: готово, val loss X.XXXX
[1] ngpt_775M_lr0.003: готово, val loss Y.YYYY
Все прогоны закончены.
```

После этого ячейка 5 соберёт отчёт и PDF.

**Если вместо «готово» написано «пауза (время сессии)»**, значит модель не успела за 12 часов.
Ничего не перезапускай: напиши в чат, продолжение обучения подготовим отдельно.

**Если «ОШИБКА»** — пришли в чат весь текст ошибки из Logs.
