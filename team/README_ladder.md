# Лестница бюджетов: увидеть главный результат статьи nGPT — общий план на 3 аккаунта

## Цель

Статья (arXiv:2410.01131, рис. 1–2): nGPT доходит до того же val loss, что GPT, за в несколько раз
меньшее число токенов, и **выигрыш растёт с длиной обучения**. Считается это лестницей бюджетов:
каждую модель учат на нескольких бюджетах, у каждого своё полное расписание lr (косинус до нуля),
и сравнивают итоговые loss: сколько токенов нужно GPT, чтобы дойти до loss nGPT, и наоборот.

Наше прежнее «≈1.4×» считалось иначе — по кривой одного прогона, в середине обучения nGPT, —
и потому занижено. Грубая оценка по уже готовым ступеням (150M и 775M) даёт ≈1.6×.

## Лестница целиком

| Бюджет | Токенов на параметр | GPT | nGPT |
|---|---|---|---|
| 150M | 4 | ✅ 5 lr (лучший 0.003) | ✅ 5 lr (лучший 0.006) |
| 250M | 6 | **B**: 0.003 | — |
| 300M | 8 | — | **B**: 0.0045 |
| 450M | 12 | **C**: 0.003 | **B**: 0.0038 |
| 775M | 20 | ✅ 0.0015, 0.003 (2 сида); **C**: 0.0042 | ✅ 0.003 (2 сида), 0.006; **C**: 0.002 |
| 1.4B | 36 | **C**: 0.003, 0.002 | **B**: 0.003, 0.002 |
| 2.8B | 72 | **A**: 0.003, 0.002 | — |

✅ — уже посчитано. **A / B / C** — аккаунт, который считает.

Почему так:
- GPT уходит по токенам вдвое дальше nGPT (2.8B против 1.4B): если nGPT быстрее в ~2 раза, только так
  ускорение на верхней ступени получится измерить, а не оценить «больше чем».
- На верхних ступенях у каждой модели по два lr: на длинном обучении оптимум уходит вниз, и без этого
  нельзя сказать, что GPT сравнивается в лучшей форме. Отчёт сам берёт лучший lr на каждом бюджете.
- На 775M закрываем края свипа: GPT 0.0042 (выше лучшего) и nGPT 0.002 (ниже лучшего).
- lr nGPT на 300M и 450M взяты по тому, как падал его оптимум (0.006 на 150M → 0.003 на 775M).

| A | `README_ladder_A.md` | GPT 2.8B × 2 lr | 2 сессии (~23 ч) |

| C | `README_ladder_C.md` | GPT 1.4B × 2 lr, nGPT 775M lr 0.002, GPT 775M lr 0.0042, GPT 450M | 2 сессии (~23 ч) |

Все три стартуют одновременно; вторая сессия — сразу после первой. Квота: ~23 из 30 ч на аккаунт,
остаток — запас на короткую третью сессию. Итог — примерно через сутки.

Модель везде одна: 6 слоёв, d = 384, контекст 1024, батч 64 × 1024 токенов, сид 42, один и тот же
val-набор (первые 10M токенов OpenWebText) — поэтому все ступени сравнимы с уже готовыми прогонами.

## Общий отчёт: вся лестница (делает Манул, без GPU, ~10 минут)

1. Открой свой ноутбук сбора (тот, которым собирали свип 150M, на основе `kaggle_collect.ipynb`) → **Edit**.
   Справа: **Accelerator → None**.
2. **Add Input → Your Work** (и **Shared with you**) — добавь ноутбуки:
   - сам этот ноутбук сбора (его прошлый вывод — все прогоны свипа 150M);
   - ноутбук прогона 2 (GPT и nGPT, lr 0.003, 775M);
   - `ngpt-sweep-manul` (775M: GPT 0.0015 и nGPT 0.006);
   - `ngpt-seed43`;
   - `ngpt-ladder-a`, `ngpt-ladder-b`, `ngpt-ladder-c`.

   `ngpt-ctx2048` и `ngpt-ctx4096` **не добавляй** (другой контекст; отчёт их всё равно пропустит).
3. Замени **вторую ячейку** (с циклом `for m in sorted(glob.glob(...`) целиком на эту:

```python
REPO = "https://github.com/NordManul/Project_Transformers.git"

import glob, json, os, shutil, subprocess, time
WORK = "/kaggle/working"
CODE = f"{WORK}/Project_Transformers"
if not os.path.exists(CODE):
    subprocess.run(["git", "clone", "--depth", "1", REPO, CODE], check=True)
os.chdir(CODE)
print("код:", subprocess.run(["git", "rev-parse", "--short", "HEAD"], capture_output=True, text=True).stdout.strip())

ALL = f"{WORK}/all"
os.makedirs(f"{ALL}/runs", exist_ok=True)
# любая папка прогона, лежащая прямо в папке runs: и вывод обучения (runs/<запуск>/runs/<прогон>),
# и вывод прошлого сбора (all/runs/<прогон>)
for m in sorted(glob.glob("/kaggle/input/**/runs/*/metrics.jsonl", recursive=True)):
    src = os.path.dirname(m)
    name = os.path.basename(src)
    if '"type": "final"' not in open(m, encoding="utf-8").read():
        print("не закончен, пропускаю:", src)
        continue
    cfg = json.load(open(f"{src}/config.json", encoding="utf-8"))
    key = {k: cfg["args"].get(k) for k in ("lr", "seed", "data_seed", "block_size", "max_iters", "batch_size")}
    dst, n = f"{ALL}/runs/{name}", 1
    while os.path.exists(dst):
        old = json.load(open(f"{dst}/config.json", encoding="utf-8"))
        if cfg["model_name"] == old["model_name"] and key == {k: old["args"].get(k) for k in key}:
            break   # тот же прогон (ноутбук добавлен дважды или через прошлый сбор)
        n += 1
        dst = f"{ALL}/runs/{name}_v{n}"
    if os.path.exists(dst):
        print("уже есть такой прогон, пропускаю дубль:", src)
        continue
    shutil.copytree(src, dst, ignore=shutil.ignore_patterns("*.pt"))   # веса не нужны
    print(f"{os.path.basename(dst):32s} lr {cfg['args']['lr']:<8g} сид {cfg['args'].get('seed', 42):<4} "
          f"контекст {cfg['args'].get('block_size')} код {cfg.get('git_commit', '?')}")
```

4. **Run All** (интерактивно, без Commit). Во второй ячейке должен получиться список примерно из
   30 прогонов. В `/kaggle/working` появится **`sweep_report.pdf`**.

Что смотреть в отчёте:
- главный график, **левая панель** — итоговый val loss от бюджета для обеих моделей (как рис. 1 статьи);
- главный график, **правая панель** — ускорение nGPT на каждой ступени: растёт ли оно с длиной обучения;
- раздел «Итоговый val loss по бюджетам» — вся лестница с лучшим lr на каждой ступени;
- раздел «Ускорение nGPT» — те же числа списком, в обе стороны.

Промежуточный отчёт можно собрать и раньше, когда закончится часть прогонов: незаконченные пропускаются.
